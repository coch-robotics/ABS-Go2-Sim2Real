复现说明 Overview

原工作。 Agile But Safe (ABS, RSS 2024) 让四足机器人在杂乱环境中 高速移动的同时避免碰撞：用一个敏捷策略 (agile policy) 追求速度， 一个恢复策略 (recovery policy) 在危险时接管，两者由一个基于 可达性 (reach-avoid) 值函数的安全门限协同切换，并配合一个 从感知预测碰撞风险的网络。

本复现的定位。 本项目不是简单跑通官方代码，而是把 ABS 迁移到本实验室的硬件平台 —— Unitree Go2 + RealSense D435i （前向深度→2D ray）+ Livox MID360（侧/后向 2D lidar 与 LIO 定位） —— 并把工作重心放在 sim2real gap 的量化与对齐：先在实机上测量延迟、 负载、电机特性，再把这些测量值回灌进仿真 (real2sim) 做域随机化， 让训练出的策略在真机上可用。训练在 Isaac Gym 完成， 部署为一套 ROS 节点。

复现改动与踩坑 Changes & Pitfalls

以下每条都对应代码里的真实改动；带 （待补） 的是需要你用实测数据/视频补全的部分。

1. 硬件与感知管线适配

  • 把部署管线从原方案适配到 Go2 + D435i + Livox MID360： 新增 d435_preprocess_node / publisher_depthimg_linvel_d435 做前向深度→linvel/ray，livox_side_lidar_node / print_zed_front_lidar 处理侧后向 lidar。
  • 重写定位与避障节点（go2_pos_RA_rec_odom +706 行、 depth_obstacle_depth_goal_ros +667 行）以对接 Go2 的 里程计/控制接口与新的传感器话题。
  • 新增 lidar 增强配置 go2_pos_lidar_config 与评测脚本 play_lidar_eval：观测维度 50 → 74 （base 50 + 前向 ray2d 11 + 侧/后 lidar2d 13）。

2. real2sim：URDF 负载修正

  • 原 URDF 用的是裸 Go2 惯量（6.921 kg）。本复现把 D435i (0.072 kg @ [0.31,0,0.10]) 与 Livox MID360 (0.265 kg @ [0.15,0,0.13]) 作为点质量， 用平行轴定理合并进 base 惯量 → 质量 6.921 → 7.258 kg，质心/惯量同步修正。
  • 动机：传感器是悬臂安装，不修正会让仿真低估俯仰惯量， 策略在真机上点头/过冲。

3. real2sim：把实测差距灌进域随机化

用 tools/measure_sim2real_gap.py 与 measure_joint_limits_readonly.py 在实机上量测， 再把数值写进训练 config：

  • 关节响应：armature = 0.01（齿轮电机反射惯量，原为 0）。
  • 动作延迟：action_latency_range = [0,1] 步 （实测 sense→actuate ≈ 9 ms）。
  • 定位延迟/抖动：loc_latency_range = [1,3] 步、 loc_update_decimation = 2（LIO ≈ 25 Hz）、 yaw 随机游走 loc_yaw_drift_std = 0.005 rad/step、 偏置上限 0.10 rad。
  • 力矩-转速衰减：torque_speed_derate 开启， 用 URDF 峰值力矩/最大转速构造线性包络（floor 10%）， 防止策略学到真机做不出的急摆。
  • 前向感知延迟：front_lidar_latency_range = [1,3] 步、 decimation 2（D435i→ray ≈ 23 ms，慢于控制环）。
  • 外扰：max_push_vel_xy 0.0 → 0.5 重新开启以增鲁棒。

4. 任务与观测调整

  • 目标采样范围 0.3–3.0 m → 0.2–6.0 m（覆盖更大场地）。
  • 前向射线密度 theta_step 4.35°(21 条) → 8.7°(11 条)， 与 D435i 实际可用视场/算力匹配。
  • 对定位推出的目标向量与朝向加白噪声 （commands = 0.03），模拟 LIO 噪声。
